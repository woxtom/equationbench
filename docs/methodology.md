# EquationBench Linear Methodology

**Scoring version:** 3.0 · **Status:** integrated EQB scoring implemented

EquationBench measures one thing: can a model solve a dense integer linear
system exactly, across an increasing range of sizes? One integrated score
captures both reach and reliability.

The detailed ladder and scoring specification is in [ladder.md](ladder.md).
This page states the guarantees and the limits.

## 1. Exact ground truth

Every task is generated by a program:

1. Draw a dense integer matrix $A$.
2. Reject it if it is singular.
3. Draw a known integer solution $x$.
4. Compute $b = Ax$.
5. Ask the model for $x$.

The answer is checked by exact integer comparison after canonicalization. There
are no LLM judges, no tolerance bands, and no partial credit.

## 2. Deterministic generation

A task is a pure function of

```
(season_seed, family="linear", level, index, generator_version, prompt_version)
```

The task id is a hash of those fields plus the derived seed. The public season
seed is published, so every public task can be regenerated. A sealed holdout
is planned but not implemented yet.

## 3. Prompt and answer contract

The prompt contains the system and a short JSON answer contract. The model may
reason, but it must end with one JSON object:

```json
{"answer": [3, -1, 7]}
```

The parser accepts the JSON object, a bare bracketed list, parenthesized lists,
and labeled vectors such as `x1 = 3, x2 = -1, x3 = 7`. It is strict about values:
every entry must be an exact integer in the requested order.

## 4. Score

The single score is **EQB effective solved levels**: 1 plus area under the
non-increasing isotonic exact-solve curve, integrated in actual log system size.
Every row uses the same whole-level grid L1–L11. Half levels are diagnostics.
Additional trials refine rates, not the difficulty weights.

Missing grid knots receive monotone bounds; unresolved regions produce an
unranked range. Inferred plateaus are disclosed, not counted as observations.
The task bootstrap refits and integrates the entire curve. Small all-pass or
all-fail samples can understate uncertainty. See [ladder.md](ladder.md) for the
complete formula, bounds, horizon policy, and interval limitations.

The horizon is shared and versioned. EQB has a ceiling at a fixed horizon, but
there is no permanent ceiling across extensions. Extending an all-zero tail
does not dilute the score. Scores from different horizons are not comparable.
The v1 fixed-set score and v2 frontier/composite are retired, not relabeled.

## 5. Contamination

- The public ladder uses a published season seed.
- A sealed holdout with an unpublished seed and a published hash commitment is
  planned but not implemented yet. Until it exists, no row is checked against one.
- A new season rotates the public seed and freezes a new task bank.

Procedural generation reduces memorization risk but does not eliminate it. A
model may have seen similar systems during training. The planned sealed holdout is
the mitigation.

## 6. Cost and reasoning effort

- Official rows will use one declared reasoning setting; the actual level
  reported by the provider is recorded.
- Cost is provider-reported and shown with a cost basis. Subscription and API
  list prices are not mixed without a label.
- Prefer full-grid coverage and predeclared precision sampling. The adaptive
  runner is not implemented. Total cost depends on the selected task set, so
  cost charts are descriptive rather than controlled efficiency comparisons.
- Provider errors and timeouts are infrastructure failures, not model answers.
  They are retried and excluded from the denominator; completion rate is reported.

## 7. Limits

EquationBench Linear is a closed-book benchmark. It does not measure tool use,
multi-turn collaboration, proof writing, or approximate reasoning. It is a
stress test for exact large-state computation, not a general mathematical
ability score.

Provider-reported model identities are not independently vendor-verified. Rows
must disclose provider, route, model id, version, and pricing source.

## 8. Reproducibility

```bash
uv sync --extra dev
uv run pytest
uv run eqb ladder --max-level 20
uv run eqb ladder --max-level 10 --measure
```

A run receipt records the model, provider, route, reasoning level, dataset/task
ids, task bank hash, environment, timestamps, usage, cost, and raw responses.
