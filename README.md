# EquationBench

**Procedurally generated, exactly verifiable large-equation reasoning for language models.**

Can a model hold a thousand-term thought? EquationBench tests that directly. Every task is generated by a program, is large enough that memorization is not a strategy, and has a ground truth computed with exact integer or rational arithmetic. Models get one prompt, no tools, and one final answer. There is no LLM judge, no tolerance band, and no partial credit.

`EquationBench v1.0.0` · `dataset v1` · **default reasoning: max** · [linear ladder (10 tasks)](leaderboard-linear-ladder/index.html) · [linear-only (10 tasks)](leaderboard-linear/index.html) · [standard/off 70-task results](leaderboard-off/index.html) · [35-task preview](leaderboard-preview/index.html) · [methodology](docs/methodology.md) · [task tracks](docs/tasks.md)

## Why this benchmark exists

Most math benchmarks are collections of human-written problems. They are valuable, but they are also finite, public, and increasingly saturated. EquationBench takes a different approach:

- **Generated, not scraped.** Tasks come from seven deterministic generators with five difficulty levels. The public set can be regenerated byte-for-byte from its master seed.
- **Large by construction.** The hard tasks require hundreds of arithmetic operations, 36-factor polynomial expansions, 14×14 linear systems, 22nd-degree calculus, deep exponent towers, 10×10 determinant-of-matrix-polynomial problems, and recurrences at indices above \(10^{18}\).
- **Exact by construction.** Ground truth is never an estimate. A model either produces the exact integer/rational/vector or it does not.
- **Contamination resistant.** The generator is public; the sealed holdout seed is not. The open leaderboard is reproducible; the closed holdout is used to validate top entries and future seasons.
- **Auditable.** Every run stores its prompts, responses, token usage, cost, latency, and dataset hash. The leaderboard links to the run receipt.

### Repeat run and variance

A second full pass over the same ten tasks gave a useful warning about sample size:

| Model | First pass | Repeat | Note |
|---|---:|---:|---|
| DeepSeek V4.1 Flash | 39.2 | 35.0 | stable-ish |
| GPT-6.1 Sol | 88.3 | **100.0** | two 24×24 quota errors retried after the 5-hour reset; both correct |
| GPT-6 Sol | 16.7 | 25.8 | +9 points from task-level variance |
| GPT-5.6 Sol | 16.7 | stopped at 5/10 | too slow; timeouts |
| GPT-6 Luna | 0.0 | 0.0 | stable zero |

The GPT-6.1 repeat initially had two 24×24 tasks fail with **“ChatGPT user has reached their Subscription Sharing usage limit.”** That was the 5-hour account window, not a model answer. After it reset, the two tasks were retried and both were solved. The repeat is now a clean **10/10, EQB 100**.

The repeat site is at `leaderboard-linear-ladder-r2/index.html` (four clean models; GPT-5.6 Sol’s partial run is excluded). The main ten-task site remains `leaderboard-linear-ladder/index.html`.

Even with GPT-6.1 at 100 in the repeat, the 88.3 vs 100 gap shows that two tasks per size is still a small sample. The next meaningful step is **three to five tasks per size**, or multiple seeds, not another ladder change.

## The seven tracks

| Track | What it asks | Why it is hard |
|---|---|---|
| **Arithmetic** | Evaluate a deeply nested integer expression with `+ - * ^ !` | Many operations, large intermediates, no step-by-step partial credit |
| **Polynomial Algebra** | Extract one exact coefficient from a product of many linear factors | Requires combinatorics or disciplined polynomial DP at degree 36 |
| **Linear Systems** | Solve a dense integer system with a unique integer solution | Gaussian elimination on up to 14 variables, exact arithmetic |
| **Calculus** | High derivative at a point, or exact definite integral | Expand a 22-factor polynomial and differentiate/integrate exactly |
| **Modular Arithmetic** | Evaluate deep right-associative power towers modulo a large prime | Euler/CRT reasoning, not brute-force exponentiation |
| **Matrix Algebra** | Determinant, or determinant of \(A^2+cA+dI\) | Fraction-free elimination on matrices up to 10×10 |
| **Recurrences** | Evaluate a high-order recurrence at an enormous index modulo a prime | Companion-matrix or Kitamasa exponentiation |

Each track has five levels: **Warm-up**, **Working**, **Hard**, **Very hard**, and **Frontier**. The public test set has 70 tasks (2 per family × level); the development set has 35 (1 per cell); the sealed holdout has 140 (4 per cell).

## Quick start

Requires Python 3.11+ and [`uv`](https://docs.astral.sh/uv/) (or pip).

```bash
git clone <this-repo> equationbench
cd equationbench
uv venv --python 3.12
uv pip install -e ".[dev]"

# Inspect the public development set
eqb verify-dataset --path datasets/equationbench-v1-dev
eqb show-task --family modular --level 4

# Cheap default: the 10-task linear-only set
eqb run --model deepseek-v4-1-flash \
  --dataset datasets/equationbench-v1-test-linear \
  --out runs/linear/deepseek-v4-1-flash \
  --concurrency 2 \
  --timeout 0 \
  --thinking max

# Full 70-task set: replace the dataset path
# --dataset datasets/equationbench-v1-test

# Or run an OpenAI-compatible local server: see config/models.toml
```

`--timeout 0` means **no wall-clock limit**: a slow provider is not scored as wrong because its tokens arrive slowly. `--thinking max` is the default; providers that do not support `max` clamp to their highest available level and the actual level is recorded. Each run writes `predictions.jsonl`, `run.json`, and `summary.json` under `runs/`. Build the static leaderboard with:

```bash
eqb leaderboard build --runs runs/linear --dataset datasets/equationbench-v1-test-linear --out leaderboard-linear
python -m http.server 8000 --directory leaderboard-linear
# open http://localhost:8000
```

## The score

**EQB Score** is difficulty-weighted exact pass@1:

\[
\text{EQB Score} = 100 \cdot \frac{\sum_i \text{level}_i \cdot \mathbb{1}[\text{correct}_i]}{\sum_i \text{level}_i}
\]

Raw accuracy is reported too. Confidence intervals are paired cell-cluster bootstrap intervals over tasks (2,000 resamples by default), so all models are resampled on the same task draws. The leaderboard also reports rank intervals, per-track breakdowns, cost per 100 tasks, latency, and the actual reasoning level reported by the provider.

The model is instructed to end with a single JSON object such as:

```json
{"answer": "121932631112635269"}
```

The parser accepts JSON, `\boxed{...}`, LaTeX fractions, labeled solution vectors, and exact arithmetic expressions such as `2^10`. It rejects approximations. See [docs/methodology.md](docs/methodology.md) for the full answer contract.

## Reproducibility and data integrity

- Every task id is a hash of `(family, level, seed, generator version, prompt version)`.
- Every dataset has a SHA-256 hash over its full task contents.
- `eqb verify-dataset` re-generates every task and checks the answer and prompt.
- The sealed holdout is encrypted with Fernet (AES-128-CBC + HMAC-SHA256); its plaintext hash and seed commitment are published in `manifest.json`. The key lives outside the repository until the reveal date.
- `run.json` records the model, provider, thinking level, dataset hash, selected task ids, environment, git commit, and timestamps.
- The leaderboard refuses runs whose dataset hash does not match the current test set, and excludes incomplete runs by default.

## Status

`EquationBench v1.0.0` is the first public release. The harness and public datasets are complete. The default reasoning effort is now **max**. The max-reasoning full sweep hit the `opencode-go` 5-hour usage limit. It is stopped, not complete. Partial max predictions are saved; a clean full-set max leaderboard requires a refreshed key or the limit to reset. Partial direct-API DeepSeek runs are archived separately. A linear-only 10-task profile and leaderboard exist for cheap iteration. Full 70-task standard/off results are archived in `leaderboard-off`; a 35-task preview covers eight models in `leaderboard-preview`.

Known limitations of the current results:

- the max-reasoning full-set leaderboard is not built yet; the sweep hit a provider usage limit;
- model identities are provider-reported, not independently vendor-verified;
- the 35-task preview uses a 240-second timeout and is not directly comparable to the 70-task runs;
- the sealed holdout has not yet been used for a public verification;
- one fixed configuration (no tools, `max` reasoning request, no wall-clock timeout) is used for the new full-set rows.
